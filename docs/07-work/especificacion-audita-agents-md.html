Especificación: Skill audita-agents-md

§1 Resumen

Construir una skill (formato Agent Skills) que audita la coherencia de AGENTS.md y de docs/ contra el árbol real del repositorio, produce una tabla de "drift" (doc dice / árbol tiene / corrección) y, solo con confirmación humana, aplica las correcciones a AGENTS.md. La prueba de que hace falta: esta sesión encontró que AGENTS.md describía k8s/ y monitoring/ como vacíos y al backend sin dependencias, cuando el árbol decía lo contrario; ningún agente lo detectó antes de tomar decisiones sobre esa información.

§2 Objetivos

  • O1. Existe skills/audita-agents-md/SKILL.md con frontmatter name: audita-agents-md y description en una sola línea, sin placeholders ni TODO (validable con la validación del estándar Agent Skills).
  • O2. La skill ejecuta la auditoría con el árbol versionado (git ls-files, ls, lectura de archivos) y emite la tabla drift con tres columnas: doc dice / árbol tiene / corrección, agrupada por categoría (archivos, convenciones, índices).
  • O3. Ejecutada sobre este repo en modo read-only, detecta al menos: k8s/ inexistente, monitoring/ poblado, backend/pom.xml con deps de security/flyway/jwt, migraciones V1__create_rbac.sql/V2__seed_rbac.sql, .mvn/wrapper sin mvnw, y docs sin indexar en docs/README.md.
  • O4. En modo read-only el reporte no modifica ningún archivo: git status queda limpio tras la auditoría.
  • O5. En modo corrección, ninguna edición se aplica sin confirmación explícita, y tras confirmar, el re-audit baja a 0 el drift de las filas corregidas.
  • O6. Queda instalada en skills/audita-agents-md/ (repo), ~/.opencode/skills/audita-agents-md/ y ~/.agents/skills/audita-agents-md/, y empaquetada como audita-agents-md.skill (verificable con ls y unzip -l).

§3 Fuera de alcance

  • No se ejecuta la corrección de AGENTS.md: construir la skill no es aplicarla. La aplicación es la ejecución posterior, con confirmación humana.
  • No se reescriben los docs ni el índice de docs/README.md automáticamente: se reporta y se sugiere la corrección; la escritura queda para quien tenga el dueño del doc.
  • No se audita código Java ni Angular (eso es revisión de código, no de documentación).
  • No se verifica que los comandos documentados sean ejecutables (implica compilar/testear/desplegar).
  • No se tocan workflows, despliegues, ni main.

§4 Diseño

La skill es un SKILL.md con instrucciones (sin scripts obligatorios) que ejecuta 5 pasos: inventariar el árbol versionado, extraer las afirmaciones de AGENTS.md y del índice de docs/, compararlas contra el árbol, emitir la tabla drift, y —derrota por confirmación— aplicar a AGENTS.md solo las filas confirmadas y re-auditar. La fuente de verdad es el árbol versionado (lo que quedaría commiteado), no el filesystem físico con sus artefactos gitignored.

Contenido de la skill (reglas que debe codificar):

  • Verificaciones de AGENTS.md: cada archivo/ruta citada se contrasta con git ls-files; cada afirmación de estado (p. ej. "directorio vacío", "sin deps") se contrasta con el contenido real; los enlaces a archivos deben existir.
  • Verificaciones de docs/: cada doc del índice de docs/README.md existe, cada doc real del árbol está en el índice, los nombres cumplen kebab-case en inglés con prefijo numérico de categoría 0X-, y los assets referenciados existen en docs/assets/.
  • Ignorados conscientes: los directorios gitignored (node_modules/, target/, coverage/, .angular/) no generan drift.
  • Overrides: si el dueño rompe una convención a propósito, la skill acepta un mecanismo de excepción declarado (lista de exclusiones) en lugar de reportarlo como drift.

Directorio fuera de gitLa skill aborta con aviso: necesita un repositorio git como fuente de verdad.

Convención rota a propósito (override)Si hay una excepción declarada, no entra a la tabla drift; si no, se pregunta al usuario si es excepción o drift.
Reporte muy extensoSe agrupa por categoría (archivos / convenciones / índices) y se resume el total de desviaciones al inicio.

§7 Decisiones

Alcance de la auditoría AGENTS.md + coherencia de docs/ (índice y naming) Solo AGENTS.md; AGENTS.md + docs + verificación de comandos Solo AGENTS.md deja ciego el índice de docs, que es donde la sesión encontró docs sin indexar; verificar comandos ejecutables obliga a compilar/testear, que es otro trabajo.
¿Solo informa o también corrige? Reporte + auto-corrección de AGENTS.md con confirmación por fila Read-only puro; auto-corrección sin confirmación Read-only deja el fix humano byte a byte; corregir sin confirmación arriesga el archivo que gobierna al agente. El default sigue siendo no tocar nada.
Formato del reporte Tabla drift: doc dice / árbol tiene / corrección Solo lista de anomalías; tabla + revisión de PENDIENTE La columna "corrección" convierte el reporte en accionable sin reinterpretar; revisar PENDIENTE es una auditoría adicional que se difiere.
Fuente de verdad del árbol El árbol versionado (git ls-files) El filesystem físico completo El FS incluye artefactos gitignored que mienten; la skill audita lo que quedaría commiteado.

Convenciones rotas a propósito Mecanismo de excepciones declaradas (overrides) Reportar siempre como drift Un override evita falsos positivos que terminguen ignorando el reporte completo.
